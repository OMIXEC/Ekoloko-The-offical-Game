# Ekoloko Platform — Consolidated Guide

Scope: three repos, one canonical stack. This doc covers local run, online deployment, backend management, admin codes/gift cards, subscriptions, desktop builds (including macOS DMG), and safe package updates.

Canonical decision (confirmed): the **Flash game + `Ekoloko-Server-Files`** is the platform. This repo is the legacy asset mirror. The HTML5 game at `play.ekoloko.org` and a Rust rewrite are out of scope.

> **Consolidated layout (as built):** frontend at `client`, backend at `backend/server`, desktop at `desktop`, admin CLI at `admin/cli.js`, patches at `patches/`, CI at `.github/workflows/build.yml`. `scripts/bootstrap.sh` installs/builds both apps; `scripts/dev.sh` runs the backend with `GAME_ASSETS_ROOT=client`. Foreign-build URLs were stripped by `scripts/sanitize-links.py` and are blocked in CI. Paths below that say `server/` refer to `backend/server/`.

### Target architecture

```
Browser + Ruffle ──HTTPS──> nginx ──> static client (.swf, .xml, images, audio)
                              │
                              ├── /ws ──────────> Node :8080 ──bridge──> TCP :9339 (SmartFox-style)
                              ├── /ekoloko-web/ ─> Node :8080 (register / login / details)
                              ├── /ekoloko-i18n/ > Node :8080 (translations)
                              ├── /BlueBox/ ─────> Node :8080 (HTTP polling fallback)

Node :8080 ──> SQLite: server/database/ekoloko.db   (WAL mode; NOT in git)
Admin console ──> same API, privileged routes        (not implemented yet)
Desktop Electron ──> public HTTPS host (must be retargeted from play.ekoloko.org)
```

## 1. Run locally

### 1.1 Static-only preview (fast, no backend)

```bash
cd /Users/omixec/dev/github/ekoloko-both
python3 -m http.server 8080
# open http://localhost:8080/
```

Add Ruffle to a wrapper page (`index.html`, `staging/login.html`, or `ekoloko/login.html`):

```html
<script src="https://unpkg.com/@ruffle-rs/ruffle"></script>
```

Modern browsers removed Flash; without Ruffle the `.swf` files do not render. For production, download Ruffle from <https://ruffle.rs/> and self-host it.

Limitations: login, rooms, codes/cards, subscriptions do not work — they need the Node server.

Before serving, fix host hardcodes:

- Replace `http://ekoloko.cf/…` with relative paths or `window.location.origin`.
- Remove the script that rewrites `https:` to `http:` (28 files).
- Ensure `.swf` is served as `application/x-shockwave-flash`.

### 1.2 Full stack (recommended)

Requires Node.js 20+ (22 preferred), npm, git, optional nginx.

```bash
git clone https://github.com/systems7430-bit/Ekoloko-Server-Files.git
cd Ekoloko-Server-Files/server
npm ci
npm run build
EKOLOKO_HOST=localhost npm start
```

Defaults and overrides:

| Setting | Default | Env var |
| --- | --- | --- |
| SmartFox TCP | `9339` | `TCP_PORT` |
| HTTP + WebSocket | `8080` | `HTTP_PORT` |
| Public host written into client config | `play.ekoloko.com` | `EKOLOKO_HOST` |
| Client asset root | `../client` | `GAME_ASSETS_ROOT` |
| Database | `server/database/ekoloko.db` | fixed in `src/index.ts` |

To use this mirror as the asset root instead of the server repo's `client/`:

```bash
export GAME_ASSETS_ROOT=/Users/omixec/dev/github/ekoloko-both
```

The HTTP server maps `/ekoloko` → `$GAME_ASSETS_ROOT/ekoloko` and `/games` → `$GAME_ASSETS_ROOT/games`, which this repo satisfies. i18n endpoints read `$GAME_ASSETS_ROOT/ekoloko-i18n`, also present here. Config XMLs (`sfs_servers.xml`, `urls.xml`) are generated by `server/src/static/ConfigFiles.ts` into `server/config/`.

Open:

```bash
curl http://localhost:8080/health
# client entry:
open http://localhost:8080/ekoloko/login.html
```

Edit `client/conf/sfs_servers.xml` so `<ip>` / `<bb_ip>` point at your host and ports match `TCP_PORT` / `HTTP_PORT`.

### 1.3 Smoke test

1. `curl /health` returns OK.
2. Register via `POST /ekoloko-web/register.action` or `/register`.
3. Log in and confirm a room list loads.
4. Open a SWF through Ruffle and confirm `/ws` connects.
5. Check server console for `[TCP] Unhandled:` messages — these reveal unimplemented client commands.

## 2. Online deployment

The server repo's `INSTALL.md` is the authoritative Hebrew step-by-step. Summary of the production path:

1. **Host**: Ubuntu 22.04+ / Debian 12 VPS with `sudo`; ports 80/443 open; DNS A record → VPS IP.
2. **Runtime**:
   ```bash
   sudo apt update && sudo apt install -y nginx git curl
   curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   sudo apt install -y nodejs
   ```
3. **Code**: place under `/opt/ekoloko` with `server/` and `client/` siblings.
4. **Build + run**:
   ```bash
   cd /opt/ekoloko/server
   npm ci && npm run build
   ```
5. **Config**: set `EKOLOKO_HOST=<your-domain>`; update `client/conf/sfs_servers.xml`, `urls.xml`, `files_version.xml`.
6. **nginx**: serve static client directly; proxy `/ekoloko-web/`, `/ekoloko-i18n/`, `/BlueBox/`, `/static/`, `/health` to `127.0.0.1:8080`; proxy `/ws` with `Upgrade`/`Connection` headers; MIME type for `.swf`; `Cache-Control: no-store` for `.swf`/`.xml`. Full config in `INSTALL.md` §6.
7. **TLS**: `sudo apt install -y certbot python3-certbot-nginx && sudo certbot --nginx -d <your-domain>`. HTTPS required — browsers block insecure WebSocket from secure pages.
8. **Supervisor** (systemd example):
   ```ini
   [Unit]
   Description=Ekoloko Game Server
   After=network.target

   [Service]
   Type=simple
   WorkingDirectory=/opt/ekoloko/server
   Environment=EKOLOKO_HOST=your-domain.com
   Environment=HTTP_PORT=8080
   Environment=TCP_PORT=9339
   ExecStart=/usr/bin/node dist/index.js
   Restart=always
   User=www-data

   [Install]
   WantedBy=multi-user.target
   ```
   ```bash
   sudo systemctl daemon-reload && sudo systemctl enable --now ekoloko
   ```
   pm2 is the simpler alternative in `INSTALL.md` §8.
9. **Ruffle**: self-host a pinned Ruffle build; inject into login wrapper; verify `/ws`.
10. **Smoke test** from a remote machine, not only localhost.

Static-only hosting (Cloudflare Pages/Netlify/GitHub Pages) works for the mirror alone, but gives you no accounts, persistence, or admin. For a remote user base, use the VPS/container path above.

## 3. Backend management

### 3.1 What exists today

Tables created in `server/src/index.ts`: `users`, `user_items`, `user_animals`, `user_buddies`, `user_quests`, `user_house`, `user_cards`, `game_scores`, `chat_log`.

- `users.premium` is a single integer flag. There is **no subscription table, no billing, no renewal, no entitlement history**.
- `users.is_moderator` / `ranger_level` exist, but there is no admin UI and no privileged API.
- The client config points at `redeemCard.action` and `creditsRedeemCard.action` (`server/src/static/ConfigFiles.ts`), but **no such routes exist** in `HttpServer.ts`. Eko-Code / Eko-Card redemption is not implemented.
- GiftExtension only transfers inventory items between players. CardExtension handles collection/trading/pack opening — not purchased cards.
- `server/src/index.ts` seeds `Admin` / `admin123` and `TestUser` on every fresh DB.

### 3.2 Target data model (to build)

```
admin_users      id, username, password_hash, role, totp_secret, created_at, disabled
subscriptions    id, user_id, provider, provider_sub_id, plan, status, current_period_end, cancelled_at
entitlements     id, user_id, kind (premium|pioneer|…), source, granted_at, expires_at
redeem_batches   id, name, type (code|gift_card|rav_card), reward_json, expires_at, created_by, count
redeem_codes     id, batch_id, code_hash, code_hint, status, used_by, used_at, expires_at
audit_log        id, actor_id, action, target_type, target_id, metadata_json, created_at
```

Rules:

- **Stripe (or equivalent) is the billing source of truth.** Our DB keeps an entitlement snapshot kept in sync by signed webhooks. Never store card numbers.
- Codes stored hashed; show full code only once at generation; CSV export is a privileged, audited action.
- Redemption must be idempotent (unique `used_by`/`used_at`), rate-limited, captcha-protected, and validate against `ekoCode_iw.xml` / `ekoCard_iw.xml` error strings so the Flash client shows the right message.
- Admin accounts are **separate** from game `users`; no shared `admin123`, no MD5.

### 3.3 Admin dashboard

Yes — needed. Minimum screens:

1. Users: search, view, ban/unban, grant/revoke entitlement, reset inventory (audited).
2. Codes & gift cards: generate batch (prefix, count, expiry, reward JSON), list, export CSV, revoke, view redemptions.
3. Subscriptions: list, status, provider ID, cancellation, webhook failures.
4. Audit log: every privileged action, actor, timestamp, before/after summary.
5. Access control: roles `viewer`, `operator`, `admin`; TOTP 2FA; session expiry; break-glass account stored offline.

Serve it on the same domain under `/admin`, behind the same nginx TLS, with `Cache-Control: no-store` and strict CSP.

### 3.4 Operational procedures

**Generate a code/gift-card batch (once implemented):**

1. Sign in to `/admin` with 2FA.
2. Choose type (Eko-Code / Eko-Card / Rav-Card), reward JSON, quantity, expiry, optional prefix.
3. Submit → codes hashed into DB; CSV downloaded once; record batch ID in the audit log.
4. Distribute CSV to the fulfillment channel; do not paste codes into chat/tickets.
5. Revoke by batch or single code; check redemptions report.

**Subscription management:** handled at the provider (Stripe dashboard) plus our entitlement sync; dunning/renewal emails come from the provider. Our DB answers "is this user entitled?" — it does not store payment instruments.

## 4. Desktop application

### 4.1 Current state

- Electron 45.4.1, JS, package name `ekoloko-rewritten`, version 2.0.0.
- `npm install`, `npm start`, `npm run start:beta`, `npm run check`, `npm run dist` (Windows NSIS).
- CI (`.github/workflows/release.yml`) builds **Windows + Linux only** on push to `main`; version bump in `package.json` triggers a GitHub Release; `electron-updater` auto-updates installed clients.
- `src/` allows only `ekoloko.org` hosts; `EKOLOKO_ALLOW_LOCAL=1` permits localhost in dev.
- macOS: `docs/MAC_BUILD.md` says builds are manual and unsigned. `scripts/createMacDmg.js` already creates a styled DMG using `hdiutil` + `osascript`, but only runs on macOS. v2.0.0 release has no `.dmg`/`.zip`; v1.1.1 did.

### 4.2 macOS DMG — Rust or not?

**No Rust.** The DMG is already implemented in JS (`scripts/createMacDmg.js`, `build/dmg-background.png`, `npm run dist:mac:dmg`). The gap is CI and signing, not the packaging algorithm.

Recommended fix:

1. Add `macos-latest` to the release matrix in `release.yml`.
2. On that job: `npm ci` → `npm run check` → `npx electron-builder --mac zip --x64 --arm64 --publish never -c.mac.identity=null` → `node scripts/createMacDmg.js`.
3. Upload `dist/*.dmg`, `dist/*.zip`, `dist/latest-mac.yml`, SHA256 sums.
4. Test on Intel + Apple Silicon; confirm Gatekeeper first-run behavior.
5. For silent install and macOS auto-update: enroll in Apple Developer Program, set `APPLE_IDENTITY`, notarize with `xcrun notarytool`, then remove the `-c.mac.identity=null` override. Until then, users right-click → Open.

Rust would only be justified to generate DMGs on Linux CI (e.g. a Rust DMG crate). That still leaves .app signing/notarization unsolved, so it buys nothing here.

### 4.3 Retarget to our deployment

Desktop currently loads `play.ekoloko.org` (HTML5, out of scope). To point it at the Flash stack:

- Change the default URL and host allowlist in `src/main/` to your domain.
- Keep `--beta` / `EKOLOKO_URL` / `EKOLOKO_USER_DATA` switches.
- Keep Ruffle in the served wrapper; Electron does not include Flash either.
- Verify `electron-updater` release channel still points at the desktop repo.

## 5. Safe package / asset updates

1. **Lockfile is law**: use `npm ci`, never `npm install` in CI. Commit `package-lock.json`.
2. **Pin majors**: `electron` is already pinned (`45.4.1`); keep `electron-builder`, `express`, `better-sqlite3` on reviewed upgrades only.
3. **Audit**: `npm audit --omit=dev` on a schedule; review before bumping; never auto-mergeDependabot without a smoke test.
4. **Branch → test → ship**:
   ```bash
   git switch -c chore/deps-<date>
   npm ci && npm run check && npm run build
   # local smoke: /health, register, login, room list, Ruffle /ws
   ```
5. **DB first**: back up `server/database/ekoloko.db` (WAL) before any deploy that may touch schema. Schema changes need an explicit migration, not `CREATE TABLE IF NOT EXISTS` drift.
6. **Asset swaps**: replace SWF/XML **keeping the exact filename**; cache-bust via `files_version.xml`; test in Ruffle; keep the previous file for rollback.
7. **Version bump** in desktop `package.json` is the release trigger — bump intentionally, once per ship.
8. **Rollback**: keep last-known-good release artifact + DB snapshot; redeploy previous version and restore DB if health checks fail.

## 6. Security must-fix before public exposure

| Finding | Evidence | Action |
| --- | --- | --- |
| Default admin `Admin` / `admin123` seeded | `server/src/index.ts` `seedData()` | Remove from production seed; force password change on first login. |
| Unsalted MD5 passwords | `LoginExtension.ts`, `HttpServer.ts`, `index.ts` | Migrate to Argon2id/bcrypt with per-user salt; support legacy verify-on-login then rehash. |
| Wildcard CORS and `crossdomain.xml` `domain="*"` | `HttpServer.ts` | Restrict to your origin(s); Flash crossdomain policy must list explicit domains. |
| Client config has no redeem endpoints implemented | `ConfigFiles.ts` vs `HttpServer.ts` routes | Implement or disable UI entry points; never leave a dead code path visible to users. |
| Schema mismatch: extensions query `accounts`/`players`, initializer creates `users` | `LoginExtension.ts` vs `index.ts` | Reconcile before declaring login working. |
| TCP handlers emit canned responses | `server/src/index.ts` `handleTcpData()` | Verify which SmartFox commands are real; track stubs as issues. |
| SQLite DB and secrets unmanaged | `.gitignore`, fixed `DB_PATH` | Move secrets to env/secret store; add encrypted backups with restore drill. |
| Children's game: chat is logged | `chat_log` table | Add retention, moderation, privacy notice, parental-consent flow. |

## 7. Backup, restore, rollback

```bash
# hot backup of WAL-mode SQLite
sqlite3 /opt/ekoloko/server/database/ekoloko.db ".backup '/backup/ekoloko-$(date +%F).db'"

# asset snapshot
tar czf /backup/client-$(date +%F).tgz -C /opt/ekoloko client

# restore (stop server first)
sudo systemctl stop ekoloko
cp /backup/ekoloko-YYYY-MM-DD.db /opt/ekoloko/server/database/ekoloko.db
sudo systemctl start ekoloko
curl https://your-domain/health
```

Schedule daily backups + weekly restore drill. Keep at least 3 generations off-host.
